# Milestone 0 — Foundations: Vault, Index & App Shell

Parent: [`milestones.md`](../../milestones.md)

## Objective

Stand up the three lowest layers of `design.md`'s architecture (Vault → Index → State/Presentation shell) plus a thin end-to-end path that proves them working together, so M1 can build capture features without touching foundations.

## Exit criteria

1. `packages/citrinium_core` is a pure-Dart package (no Flutter import possible) containing vault I/O, parser, and index.
2. Parsing any fixture file and re-serializing returns **byte-identical** output. Enforced as a property test over a deliberately nasty fixture corpus.
3. A single-line edit (e.g. task state change) provably alters **only** the expected byte range.
4. Deleting the index database and relaunching reconstructs identical index state from files alone (P-11's central claim, made testable).
5. Editing a `.md` file in an external editor updates the running app's UI without restart.
6. App builds and runs on Linux, Android, and one of macOS/Windows. `web/` is gone.
7. CI runs `flutter analyze` + both test suites green.
8. `docs/file-schema.md` exists as a DRAFT FR-04 spec.

## Decisions locked for M0

| Area | Decision |
| --- | --- |
| Parser architecture | **Offset-preserving overlay** over authoritative `rawText`; entities hold offsets, edits are splices. Byte-stability by construction, not by testing. Derived from `design.md` §7 + §10. |
| Offset units | **Dart `String` code-unit offsets** everywhere; UTF-8 encode/decode only at the file boundary. Non-negotiable given emoji metadata (`📅⏰🔁`) are surrogate pairs. |
| Repo layout | Pub workspace: root = Flutter app, `packages/citrinium_core` = pure Dart. |
| Vault location | Desktop: user-picked dir (`file_selector`). Mobile: app documents dir. iOS additionally sets `UIFileSharingEnabled` + `LSSupportsOpeningDocumentsInPlace` so the vault appears in Files.app. |
| Android storage | App-private only for M0. `MANAGE_EXTERNAL_STORAGE` / "device storage" deferred — it only matters once external sync tools do (FR-01), and SAF is ruled out permanently (no file-watching, per Obsidian's own documented findings). |
| Index location | `<appSupport>/index/<hash(vaultPath)>.sqlite` — **never** inside the vault, so a future sync layer can't sync the cache. |
| Vault config | `.citrinium/` inside the vault (portable, travels with vault), excluded from scan/index. |
| Watcher | `package:watcher`'s `DirectoryWatcher` behind our own interface. iOS is polling-only (dart:io watch unsupported there); Linux recursion is handled by the package, not dart:io. |
| Generated code | `*.g.dart` / `*.freezed.dart` **not** committed; CI runs `build_runner` before analyze/test. |

## Workstreams

### W0 — Repo & toolchain (~1–2 days)

- **Spike first:** verify a Flutter app at the repo root can serve as a pub workspace root with a member package (`dart pub workspace list` should show both). Docs only illustrate a stub root. **Fallback if it fails:** move the app to `packages/citrinium_app/` (carrying `android/ios/linux/macos/windows`) and make root a stub — do this *before* writing code, not after.
- Create `packages/citrinium_core` with `resolution: workspace`.
- Fix root `pubspec.yaml` description (still says "A new Flutter project.").
- **Delete `web/`**; remove the `web` platform entry from `.metadata`.
- Shared `analysis_options.yaml` with `analyzer: language: {strict-casts, strict-inference, strict-raw-types}` + `errors: invalid_annotation_target: ignore` (freezed needs it), plus `custom_lint` for `riverpod_lint`.
- **Replace `lib/main.dart` and `test/widget_test.dart` wholesale** — per AGENTS.md, these are unmodified template files, not code to patch.
- GitHub Actions: build_runner → analyze → `dart test` (core) → `flutter test` (app). Cache the sqlite3 build-hook binaries, since the first build per platform downloads them from GitHub releases.

### W1 — Vault I/O (pure Dart) (~2–3 days)

- Path normalization incl. **Unicode NFC/NFD** handling (APFS returns NFD filenames; wikilink resolution will silently fail on accented names otherwise).
- Read/write preserving **BOM, line endings (LF/CRLF/mixed), and trailing-newline presence**.
- **Atomic writes** (temp file + rename within the same directory) so a crash mid-write can't truncate a user's note.
- `VaultScanner`: enumerate `.md`, apply ignore rules (`.git`, `.obsidian`, `.citrinium`, `.trash`, `node_modules`, dotfiles), file size cap, symlink policy.
- `VaultWatcher` interface + `watcher` impl with debounce and **self-write suppression** (must ignore events caused by our own writes, or every save triggers a reparse loop).

### W2 — Markdown parser/serializer (pure Dart) — the core deliverable (~4–6 days)

- `MarkdownDocument { String rawText; Frontmatter? fm; List<ParsedLine> lines; }`, all spans as offsets into `rawText`.
- Frontmatter: recognized **only** at offset 0; parsed with `yaml`, edited surgically with `yaml_edit` on the raw substring so user comments/formatting survive.
- Line classification per `design.md` §3.1: `- [ ] / [/] / [x] / [>] / [<] / [-] / [w]`. **Unknown marker chars are preserved verbatim** as `UnknownState(char)` rather than normalized away — required for portability.
- BuJo event/note markers (`- ○`, `- –` from §3.2) — grammar needs pinning down in W5; §3.2 gives examples, not a spec.
- **Code-fence and indented-code awareness.** `- [ ]` inside a ``` fence must not parse as a task, and wikilinks inside code must not become links. This is the single most likely source of data-corruption bugs.
- Inline metadata extraction *with spans*: `📅 date`, `⏰ time`, `🔁 recurrence`, `@context`, `#tag`, `^blockid`.
- Wikilink extraction with spans: `[[target]]`, `[[target|alias]]`, `[[target#heading]]`, `![[embed]]`.
- Edit API returning new documents via splices: `setTaskState`, `upsertInlineField`, `removeInlineField`, `appendLine`.
- Serializer is literally `rawText` — that's the whole point of the design.

### W3 — Index layer (drift, pure Dart) (~3–4 days)

Tables sized to what M1 needs:

- `documents(id, relPath, sha256, mtimeMs, sizeBytes, docType, title, frontmatterJson, indexedAtMs)`
- `entries(id, documentId, lineIndex, charStart, charEnd, blockId, kind{task|event|note|untyped}, taskState, text, dueDate, dueTime, recurrenceRaw, signifier)`
- `entry_contexts(entryId, context)` / `entry_tags(entryId, tag)` — join tables, not CSV columns
- `links(sourceDocumentId, sourceEntryId?, targetRaw, targetDocumentId?, kind{wikilink|embed})`
- `document_fts` — FTS5 virtual table created now, query-tuned in M9
- `index_meta(key, value)` holding `schemaVersion`, **`parserVersion`**, `vaultFingerprint`

Mechanics: full scan on an isolate; incremental upsert on watcher events keyed on `sha256` (skip unchanged). **A `parserVersion` mismatch triggers a full rebuild** — this is what makes parser changes safe. Reactive `Stream` queries are the boundary the state layer consumes.

### W4 — App shell + walking skeleton (Flutter) (~3–4 days)

- `ProviderScope`, `go_router`, Material 3 calm-default theme (light/dark), honoring P-07/A-07.
- First-run vault selection: desktop directory picker; mobile auto-provisions app documents dir; path persisted in `shared_preferences`.
- iOS `Info.plist`: `UIFileSharingEnabled`, `LSSupportsOpeningDocumentsInPlace`.
- Riverpod providers over core: vault, index, document list stream, entries stream.
- Four screens: first-run/vault picker → document list (from index) → read-only raw file view (`SelectableText`; **no editor** — that's §7 work in M1) → settings with vault path, index stats, and a **"Rebuild index"** button.

### W5 — FR-04 schema draft (~1–2 days)

`docs/file-schema.md`, marked DRAFT (frozen in M12): file/folder conventions, `citrinium:` frontmatter fields per type, task marker table, inline metadata grammar with precedence and escaping rules, block ID format, wikilink forms, ignore rules, encoding/line-ending policy, unknown-marker preservation rule, and an explicit open-questions list.

### W6 — Test suite (~2–3 days, interleaved)

- **Fixture corpus** of deliberately hostile files: CRLF, BOM, no trailing newline, tabs, code fences containing `- [ ]`, `---` in the body, frontmatter with comments/anchors, emoji-dense lines, NFC vs NFD filenames, very long lines, nested lists, Obsidian callouts.
- Round-trip property test: `parse(x).rawText == x`, byte-for-byte, for every fixture.
- Mutation locality test: one edit ⇒ prefix and suffix bytes provably unchanged.
- Rebuild determinism test: scan → snapshot → wipe → rescan → identical.
- Watcher convergence test on a temp dir (polling-tolerant timeouts).
- One widget smoke test: app boots to vault picker.

**Rough total: ~16–24 working days.** W1/W2/W3 are sequential-ish; W5 can run in parallel; W2 is the schedule risk.

## Risks

| Risk | Mitigation |
| --- | --- |
| Pub workspace with Flutter app at root may not resolve | Spike as the very first task; fallback is relocating the app under `packages/` |
| sqlite3 build hooks need network on first build per platform | Cache in CI; document for contributors |
| iOS watcher is polling-only | Accept for v1; flag in `design.md` §2 notes; revisit with a native `DispatchSource` impl if latency hurts |
| macOS NFD filenames break link resolution | Normalize at the vault boundary; NFC/NFD fixtures in the corpus |
| Watcher self-write echo loops | Explicit suppression window keyed on path + hash of our own writes |
| Code-fence false positives corrupt files | Fixture-driven; treat as data-integrity bug class, not cosmetic |

## Explicitly out of M0

Markdown Live Preview editor (§7 — reduced scope in M1, full scope in M6), NL date parsing (C-04, M1), any task mutation UI, search UI (M9), recurrence/habits (M7), notifications (M8), plugins (M11), Android device-storage mode, multi-vault (FR-10, post-1.0).

## Commit convention

Conventional Commits for code (`feat:`, `fix:`, `chore:`, `test:`, `refactor:`, `ci:`), scoped to the workstream where useful (e.g. `feat(vault): ...`, `feat(index): ...`). Reference requirement IDs in the body where a commit implements one, e.g.:

```
feat(vault): add offset-preserving markdown parser

Implements checkbox task-state parsing, frontmatter, and inline
metadata extraction per D-02/D-15/FR-04.
```

Doc-only commits keep the existing `docs: <Capitalized summary>` style.
