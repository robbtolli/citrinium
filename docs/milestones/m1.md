# Milestone 1 — Capture Loop: Inbox, Rapid Log & Today's Combined View

Parent: [`milestones.md`](../milestones.md)

## Objective

Ship the first true end-user feature loop on top of M0's foundations and M6's completed [`LivePreviewEditor`](../../lib/core/editor/live_preview_editor.dart):
- A unified `Entry` domain model (task/event/note/untyped, `D-01`).
- **Today's Combined View** as the default home surface (collapsible **Today's Focus Shelf** at the top + `daily/<date>.md` rapid-log stream below, `B-01`, `E-02`).
- A dedicated **Inbox** (`inbox.md`, `C-02`) and a persistent **Quick Capture bar** with a **sticky `[ Inbox | Today ]` toggle** (`C-01`, `P-01`, `P-02`).
- **In-place task editing everywhere (`D-19`, `B-05`):** clicking/tapping any task in Inbox, Today's Focus Shelf, or any task list edits it directly in-place (splicing updates into the source `.md` file in the background) without navigating away to the containing document, while offering a `[📄 source-note ↗]` badge to peek at or open the note when surrounding context is wanted.
- **Session continuity & onboarding safeguards (`A-06`, `A-08`, `N-04`):** 2-hour session restore on relaunch, a `🕒 Recent` views/documents switcher (plus `↩ Resume` chip after ≥2h), and a 14-day historical open-task filter safeguard when attaching an existing Obsidian/Markdown vault.
- Natural-language date parsing (`chrono_dart`, `C-04`).

## Prerequisite status

**M0 (Vault, Index & App Shell) and M6 (Full Live Preview Editor) are complete.** M1 builds directly on M0's `IndexService`/`MarkdownDocument` splice APIs and mounts M6's [`LivePreviewEditor`](../../lib/core/editor/live_preview_editor.dart) rather than building a separate reduced-scope editor.

## Exit criteria

1. `inbox.md` (single perpetual file, vault root) and `daily/<date>.md` (one file per day)
   are both created lazily on first use — never pre-generated — per B-09/D-11.
2. A unified `Entry` domain model (task / event / note / untyped, per D-01) exists in
   `core/domain`, sourced from the M0 index, and exposed to the UI via Riverpod
   `StreamProvider`s — no widget talks to the parser or vault layer directly.
3. **Quick Capture with Sticky Destination Toggle**: from the persistent Quick Capture bar
   (or directly inside the Inbox / Daily Log views), typing a line and pressing enter
   appends a new rapid-log line to the selected target (`Inbox` or `Today`, remembered
   across sessions via a sticky `[ Inbox | Today ]` toggle) in ≤2 interactions (P-02, C-01),
   with no forced type/tag/folder/context selection at capture time (P-01).
4. Typing a date/time phrase (e.g. "tomorrow 5pm") into a captured line is recognized via
   `chrono_dart`; the user confirms the detected date/time (no silent rewrite — see
   Risks); on confirmation the matched phrase is stripped from the visible text and
   replaced with structured `📅`/`⏰` inline metadata via the M0 parser's
   `upsertInlineField` edit API. Every other byte of the file is unchanged.
5. Checkboxes render as tappable glyphs in the Live Preview editor; tapping
   cycles task state via `setTaskState`, and the change is atomically written to disk.
6. **In-place task editing & one-gesture actions (D-19, A-03, B-05)**: every task row in
   Inbox, Today's Focus Shelf, or task lists supports one-gesture **reschedule**,
   **migrate**, **drop**, and **pin to Today's Focus Shelf**, plus **inline expansion** to
   edit its title, metadata (`📅`, `⏰`, `@context`, `#tag`), or indented note body
   directly in place without navigating away from the current screen. A source badge
   (`[📄 note ↗]`) opens a peek preview or navigates to the source document only when the
   user explicitly asks for surrounding context. **Snooze** is explicitly stubbed/hidden
   with an in-UI note that it depends on reminders infrastructure not yet built (M8).
7. A rapid-log line can carry an indented Markdown note body (D-14) and/or a short
   plain-text comment (D-18), stored as ordinary indented lines beneath it and grouped
   into a parent/child relationship computed by the **domain layer** (not the parser —
   see Decisions) from M0's flat, per-line parse output.
8. Every UI string introduced by this milestone passes an explicit supportive-tone audit
   (A-02): no shaming copy for a dropped task, an overdue item, or a skipped day.
9. **Launch continuity, missed-day resume & existing-vault safeguard (A-06, A-08, B-09, N-04)**:
   - Relaunching within **<2 hours** restores the exact last active view/document; relaunching after **≥2 hours** opens **Today's Combined View** with a `↩ Resume` chip for the prior document/view, alongside a **`🕒 Recent` Views/Documents switcher**.
   - Opening the app after any number of idle days silently creates today's Daily Log on first use with no penalty UI.
   - Attaching an existing vault with >10 open undated tasks in files older than 14 days prompts to **surface only open tasks from the last 14 days by default** in action lists.
10. Capture works fully offline (C-05), verified with networking disabled — `chrono_dart`
    and everything else this milestone adds must be 100% local.
11. `flutter analyze` and both test suites (`citrinium_core` + app) are green in CI,
    including new tests for the domain-layer Entry model, in-place splice editing,
    NL-parsing splice behavior, and launch/session continuity.

## Decisions locked for M1

| Area | Decision |
| --- | --- |
| Default Home & Navigation | **Hybrid Dual-Track shell (`design.md` §6.2)**: **Today's Combined View** is the default home screen (collapsible **Today's Focus Shelf** for up to Top 3 pinned tasks + hard events at top, `daily/<date>.md` Live Preview editor below), paired with navigation to **Actions & Inbox**, **Horizons & Review**, and **Notes & Index**, plus a **`🕒 Recent` Views/Documents switcher** in the header. |
| Session Continuity | **2-hour restore window (`A-08`)**: reopening within <2 hours restores the exact last active view/document; reopening after ≥2 hours opens Today's Combined View with a `↩ Resume` chip for the last view/document. |
| Inbox & Quick Capture | Dedicated **`inbox.md`** at the vault root — a single perpetual file, distinct from dated Daily Log files. The persistent Quick Capture bar features a **sticky `[ Inbox | Today ]` toggle** (`C-01`) that remembers the user's last selected destination. |
| In-place task editing (`D-19`) | Clicking/tapping a task in any list or on Today's Focus Shelf expands an **inline editor right inside that list** and splices edits directly into the owning `.md` file via `(documentId, lineIndex, charStart, charEnd)` — never forcing navigation to the source note. A `[📄 note ↗]` badge lets the user peek at or open the source document only when desired. |
| Existing-vault safeguard (`A-06`) | When attaching an existing vault with >10 undated open tasks in files older than 14 days, prompt to **surface only tasks from the last 14 days by default** (stored as an operational filter setting) so action lists aren't flooded on day one. |
| NL date parsing | **`chrono_dart`** (pub.dev port of chrono-node). Returns both a `DateTime` and the matched phrase's text position, which maps directly onto this codebase's span-based edit model — the matched span is exactly what gets spliced out and replaced with `📅`/`⏰` metadata. English-only for v1, consistent with the app's scope. |
| Editor scope | **Mounts M6's completed [`LivePreviewEditor`](../../lib/core/editor/live_preview_editor.dart)** directly inside Today's Daily Log and Inbox, adding interactive checkbox tap-to-toggle (`setTaskState`). |
| Note-body / comments (D-14, D-18) | Computed in `core/domain` as an indent-based parent/child grouping over M0's existing flat `List<ParsedLine>` — **not** a parser/M0 change. One level of nesting only for M1; deeper nesting is explicitly out of scope (see Risks). |
| Entry identity | `(documentId, lineIndex)` plus content-hash-assisted re-matching across incremental reparses, used for UI stability (list diffing, widget keys). Automatic block-ID (`^abc123`) assignment on every new line is explicitly **not** done in M1 — deferred until threading/backlinks (N-02) actually need it, to avoid adding visual noise to rapid-log lines before there's a feature that uses it. |
| Snooze scope | Reschedule/drop/migrate ship in M1. Snooze (time-based re-notification) is stubbed and visibly disabled until reminders (new M8) exist — consistent with B-05/A-03's "everywhere tasks appear" intent without faking a capability that isn't real yet. |
| Capture flow shape | Capture is modeled as a plain method/`AsyncNotifier`, **not** a `freezed` sealed-state ritual `Notifier`. `design.md` §6 reserves that pattern for genuinely multi-step flows (Clarify, Migration, Review); a single-line append is not one of those. |

## Dependencies to add

**Root app** (or a new pure-Dart `core/nlp` module if kept engine-agnostic): `chrono_dart` ^2.0.2.

No other new dependencies expected — this milestone builds on M0's `drift`, `flutter_riverpod`, and parser/vault packages.

## Workstreams

### W1 — Domain: unified `Entry` model (pure Dart, `core/domain`) (~3–4 days)

- `Entry` union (task / event / note / untyped) wrapping a `ParsedLine` plus its owning
  document's id/`relPath`, per D-01.
- Entry identity & stable-diffing strategy across reparses (`documentId` + `lineIndex` +
  content-hash heuristic — see Decisions).
- Indent-based child-line grouping for note bodies (D-14) and comments (D-18), computed
  purely from the flat `List<ParsedLine>` M0's parser already produces.
- Mapping from the M0 drift `entries` table rows to `Entry` domain objects.
- Use-cases as thin wrappers around `MarkdownDocument`'s existing edit API + vault write +
  index upsert: `captureLine(text, targetFile)`, `setEntryState`, `rescheduleEntry`,
  `dropEntry`, `migrateEntry`.

### W2 — Natural-language date/time parsing (pure Dart) (~2–3 days)

- Wrap `chrono_dart`: parse free text, locate the matched phrase's span, map results to
  `📅`/`⏰` metadata writes via `upsertInlineField`, and strip the matched phrase from the
  line's visible content span on user confirmation.
- Handle ambiguity: multiple date phrases in one line, time-only vs. date+time, relative
  ("in 3 days") vs. absolute phrases.
- Decide and document (updating the FR-04 draft) the precedence when a line already has
  an explicit `📅` and a new NL phrase is typed: replace vs. append vs. prompt.
- Property tests: for any fixture phrase, `capture(text with NL phrase)` changes
  `rawText` in exactly the matched span and nowhere else.
- Explicit **false-positive fixture set**: ordinary rapid-log text that should *not*
  trigger a date match (see Risks).

### W3 — Inbox & Daily Log file conventions (~1–2 days)

- `inbox.md` (vault root, single perpetual file) and `daily/<date>.md` (create-on-first-use)
  conventions, built on M0's `VaultFileIO`/atomic-write primitives.
- `getOrCreateInbox()` / `getOrCreateDailyLog(date)` vault-layer helpers.
- Update `docs/file-schema.md` (FR-04 draft, started in M0 W5) with `inbox.md`'s concrete
  location/frontmatter (if any) and the daily-log naming convention, since design.md §3.4
  only sketches this.

### W4 — Riverpod state layer for capture (~2–3 days)

- `StreamProvider`s over drift queries: entries-for-document for `inbox.md` and for
  today's daily log.
- A plain capture `AsyncNotifier` (see Decisions — not a sealed-state ritual Notifier).
- Confirm vault-watcher → index-upsert → provider-stream plumbing (built in M0 W3/W4)
  actually reaches these new providers; this is the first real consumer of that path.

### W5 — Interactive checkbox & in-place task editor wiring (`core/editor` + `shared/widgets`) (~2–3 days)

Since M6's [`LivePreviewEditor`](../../lib/core/editor/live_preview_editor.dart) is already built, this workstream connects interactive task mutations to it and builds the reusable **In-Place Task Row Editor (`D-19`)**:
- Tapping a rendered task checkbox in `LivePreviewEditor` invokes `setTaskState` and saves through `EditorSavePipeline`.
- Reusable `TaskRowItem` widget for aggregated lists (Today's Focus Shelf, Inbox task list, and future M2/M5/M10 views) that expands inline on click/tap to edit task text, `📅` date, `⏰` time, `@context`, `#tag`, and indented note body (`D-14`) by splicing directly into the source `.md` file without navigating away.
- Source badge (`[📄 relPath ↗]`) on each `TaskRowItem` that opens a peek sheet of the surrounding lines in the source note, with an optional button to open the full document.

### W6 — Today's Combined View, Inbox View, Quick Capture Bar & Session Continuity (`features/daily_log`, `features/inbox_clarify`, `app/`) (~4–5 days)

- **App shell & navigation pillars (`design.md` §6.2):** Today (default), Actions & Inbox, Horizons & Review (placeholder/Daily entry point until M4/M5), and Notes & Index (wrapping M0's document list), plus the header **`🕒 Recent` Views/Documents switcher** (`N-04`).
- **2-hour session continuity (`A-08`):** track last active route/document and timestamp; restore directly if `<2 hours` elapsed, or open Today's Combined View with a `↩ Resume` chip if `≥2 hours`.
- **Existing-vault 14-day historical task safeguard (`A-06`):** when a vault is attached with >10 open undated tasks in files older than 14 days, prompt to filter action views to the last 14 days by default.
- **Today's Combined View:** collapsible **Today's Focus Shelf** (up to Top 3 pinned tasks + today's events) at the top, and `daily/<date>.md` in `LivePreviewEditor` below.
- **Inbox View:** `inbox.md` in `LivePreviewEditor` + structured task list mode supporting in-place editing (`D-19`).
- **Persistent Quick Capture Bar:** bottom bar / hotkey input with the **sticky `[ Inbox | Today ]` toggle** (`C-01`) and inline `chrono_dart` date/time chip confirmation.
- One-gesture task-row actions: complete, migrate, drop, reschedule, and pin to Today's Focus Shelf.
- Copy/visual audit pass for A-02 (supportive tone) and A-07 (functional-first, no decoration-first templates).

### W7 — Note body & comments (D-14, D-18 cheap-adjacent) (~2 days)

- Expand/collapse affordance on any row that has child lines.
- Editing a note body opens the same reduced editor, scoped to just that line's
  child-line range — still literal file text underneath, no separate storage.

### W8 — Test suite (~2–3 days, interleaved)

- `Entry`-model unit tests: identity stability across reparse, child-line grouping edge
  cases (mixed tabs/spaces indent; explicitly excludes multi-level nesting — see Risks).
- `chrono_dart` integration tests against a fixture corpus of phrases expected to match,
  and a corpus expected **not** to match (false-positive guard).
- Widget tests: capture-to-file round trip (type text, submit, assert the file on disk
  matches expectation byte-for-byte outside the edited region).
- Golden tests for the reduced decoration set (checkbox states, signifiers, bold/italic).

**Rough total: ~20–28 working days**, not counting whatever remains of M0's W3–W5. W5
(the editor) is the schedule risk, same as W2 was for M0.

## Risks

| Risk | Mitigation |
| --- | --- |
| M0 not actually complete (index/app shell/schema doc) | Explicit gate at the top of this document; do not silently start M1 UI work against a stubbed index |
| `chrono_dart` false-positives on ordinary text (e.g. "May 3rd project" not meant as a date) | Require user confirmation before stripping/rewriting a line (per exit criterion 4) — same "no silent action" spirit as X-05, even though this isn't an AI feature |
| Reduced-scope editor still hits the hardest part of custom text editing (IME composition vs. decoration overlay) even at small scope | Budget schedule as if it were the full editor's core risk, just a smaller surface; don't assume "reduced scope" means "reduced risk" |
| Domain-layer indent grouping (W1) drifting from the parser's own code-fence/indent handling (M0 W2) | Share fixture files between the parser's test corpus and the domain layer's grouping tests |
| Multi-level note-body nesting silently mis-grouping | Explicitly restrict to one level of nesting for M1; document as a known limitation, not a bug, until revisited |

Full Live Preview decoration set (wikilinks, embeds, block-ID styling — new milestone
between M5 and M6). Clarify flow (G-01, M3). Migration ritual (B-06/B-07, M5). Monthly/
