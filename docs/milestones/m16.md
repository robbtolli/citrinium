# Milestone 16 — "The User Owns Their Data": Bidirectional Task Sync, Background Work Manager, Snapshot Export, Schema Docs, CLI & MCP Server

Parent: [`milestones.md`](../milestones.md)

## Objective

Deliver the full "The User Owns Their Data" architecture (`P-11`, `D-15`, `T-02`, `FR-04`, `FR-12`, `FR-13`, `FR-16`):
- Bidirectional task synchronization between Markdown notes (`<!-- citrine:task=<id> -->`) and SQLite (`task_id`, `source_rel_path`, `source_byte_offset` hint + scan fallback + DB-only detachment).
- UI-created tasks stored directly in SQLite with no backing `.md` file.
- Dismissible prompt banner when external `.md` files contain untagged tasks, backed by a non-blocking `BackgroundWorkManager` with an unobtrusive progress bar and an app-close confirmation dialog.
- Static Markdown snapshot export for any data view (with clear snapshot notice), full import/export, documented SQLite & Markdown schemas, the `citrine` CLI, and the `citrine-mcp` MCP server.

## Exit criteria

1. Typing a task line in any Markdown note and navigating away from that line saves the task to SQLite (`task_id`, `source_rel_path`, `source_byte_offset`) and appends a hidden `<!-- citrine:task=<id> -->` comment to the line.
2. Updating a task in a note updates SQLite; updating a task in any data view updates SQLite and updates the source `.md` file via `(source_rel_path, source_byte_offset)` hint first, then full-file scan, or clears `source_rel_path`/`source_byte_offset` (making the task DB-only) if the file or comment is missing.
3. Tasks created from the Citrine UI (not typed inside a note) are stored in SQLite with `source_rel_path = NULL`.
4. External edits to `.md` files update tagged tasks (`<!-- citrine:task=<id> -->`) automatically, and trigger a dismissible banner when untagged tasks are detected (*"Citrine has detected new markdown files in the vault that contain tasks. Would you like to import them?"*).
5. Clicking `Yes` on the banner imports those tasks and writes task ID comments in the background while showing an unobtrusive loading bar and an app-close confirmation dialog if the user tries to close Citrine during background work.
6. Any data view can be exported to a `.md` file, with the export UI clearly stating that exported files are static snapshots and will not auto-update when data changes.
7. SQLite and Markdown schemas are documented in `docs/file-schema.md`, and both the `citrine` CLI and `citrine-mcp` MCP server support querying, exporting, creating, and updating data.
8. `flutter analyze` and all unit/widget/CLI/MCP tests pass.
